<h2>先分清两件事：线路带宽和服务器配置，是两笔独立的账</h2>
<p>「带宽多大」问的是这条线路能跑多少流量，「服务器配置」问的是那台机器能扛多少运算与并发。两者相关但不是一回事：带宽给够了，机器性能不足照样卡；机器很强，带宽不够也只能干等。</p>
<p>采购时最常见的问题是把两者混在一起谈，结果一方面是带宽买多了浪费，另一方面是机器配置选低了成为瓶颈。</p>

<h2>带宽要看三个方向，不是只看「多少兆」</h2>
<p>下行：从外网到你这边的速度，多数场景够用就行。上行：从你这边往外的速度，双 ISP 住宅资源的上行通常是短板，做上传、推流业务时要重点确认。并发：同时能跑多少连接，这一项不写在带宽里，但直接影响体验。</p>
<p>三个方向里，上行最容易被忽略。标称 100M 的线路，上行可能只有 10M 甚至更低，跑批量上传时差别非常明显。</p>

<h2>按业务类型定带宽</h2>
<p>日常网页操作、账号管理这类，对带宽要求不高，稳定比快更重要。批量上传图片视频、需要同步大文件的，上行是关键指标。多设备同时使用，要把并发和总带宽一起算，不能按单设备估算。</p>
<p>建议按「峰值同时在线设备数 × 单设备典型需求」估算，再留三成余量。按平均值估算一定会不够，因为业务总有集中时段。</p>

<h2>服务器配置怎么选</h2>
<p>这类线路上的机器主要做转发，不做重计算，所以 CPU 不必追高。更该关注的是网卡数量与性能、内存是否够跑代理与日志、以及散热与供电稳定性。</p>
<p>内存的估算方法是：基础系统占用加上每个并发连接的缓冲开销。连接数上千时，内存会明显吃紧，这时候加内存比换 CPU 有效。</p>

<h2>双 ISP 对配置有额外要求吗</h2>
<p>有的，但不大。双 ISP 形态需要在配置上体现两个运营商的路径，通常意味着要有两个网络出口或者支持多路径的路由设置。这对网卡数量和路由能力提出了一点要求。</p>
<p>如果只做单路径转发，那双 ISP 的特征在外部仍能看到（因为那是地址属性），但内部并没有真正利用两个出口。要不要真做双路径，取决于业务是否有冗余需求。</p>

<h2>带宽不够时的三种处理</h2>
<p>一是升档。多数服务商支持，但要确认是否重新计费、耗时多久。二是分流：把非关键业务挪到别的线路，给关键业务腾空间。三是优化使用方式：减少不必要的重复传输、压缩素材、错峰执行。</p>
<p>第三种常被忽略，但性价比最高。很多「带宽不够」的情况，实际是使用方式造成的浪费，优化之后能省下一大笔升级费。</p>

<h2>配置选型的三个务实原则</h2>
<p>一是「够用加一点余量」，不要一次买很足。资源会升级，需求会变化，过度配置的钱很难收回。二是「瓶颈在哪里就把钱花在哪里」，先测出瓶颈再升级。三是「稳定性优先于峰值」，长期运行的机器，稳定比跑分重要。</p>
<p>三条原则的共同点是「先测量再决定」。凭感觉选配置，几乎一定会选错方向。</p>

<h2>验收时怎么确认带宽和配置</h2>
<p>带宽：在自己业务的高峰时段实际上传和下载一次，看是否达到预期。配置：查看实际可用资源与标称是否一致，跑一段时间的负载观察是否出现瓶颈。并发：模拟多设备同时连接，看是否出现连接失败或明显降速。</p>
<p>三项都要在真实业务时段测。厂商测速环境和你的实际使用场景差异很大，以标称值为准一定会失望。</p>

<h2>常见问答</h2>
<h3>双 ISP 住宅带宽一般多大？</h3>
<p><strong>答：</strong>差异很大，取决于资源方的线路条件。上行普遍小于下行，具体务必在下单前确认真实上行。</p>
<h3>配置越高越好吗？</h3>
<p><strong>答：</strong>不是。转发类任务对配置要求不高，瓶颈通常在带宽和线路质量上。过度配置是浪费。</p>
<h3>能自己升级带宽吗？</h3>
<p><strong>答：</strong>取决于服务商。有的支持在线升档，有的需要重新开通。下单前问清升档流程。</p>
<h3>多设备同时用会不会互相拖慢？</h3>
<p><strong>答：</strong>会，共享的是同一条线路带宽。按峰值估算并留余量，比事后抱怨有效。</p>
